# Database schema

The numbered SQL files in `../migrations/` are the **source of truth** for this schema. Apply them in order with `pnpm db:migrate`. Do not edit a migration after it has been applied; add another numbered migration instead. The runner records a SHA-256 checksum for each applied file and refuses a changed file.

All tables use standard PostgreSQL features and the `public` schema. There are no Neon-specific tables, extensions, or APIs. `DATABASE_URL` may point to Neon or another PostgreSQL provider. Moving to a different database **engine** (for example MySQL) would require translating the SQL and migration runner.

## Tables

| Area | Tables | Purpose |
| --- | --- | --- |
| Catalog | `departments`, `categories`, `products`, `product_images` | Books/Stationery, nested categories, product details and media references |
| Stock | `inventory`, `inventory_movements` | Available units and an audit trail for changes |
| Offers | `offers`, `offer_products`, `offer_categories` | Scheduled percentage or fixed discounts and their targets |
| Customers | `customers`, `customer_addresses` | Buyer details and saved addresses |
| Authentication | `user`, `session`, `account`, `verification` | Better Auth sessions, credentials and admin role |
| Shopping | `carts`, `cart_items` | Draft baskets; prices are recalculated server side at checkout |
| Orders | `orders`, `order_items`, `order_addresses`, `order_status_history` | Immutable order totals, item/address snapshots and status changes |
| Payments | `payments`, `payment_events` | Gateway attempts and idempotent webhook event IDs |
| Internal | `schema_migrations` | Applied migration names and checksums, maintained by the runner |

Money is stored as integer **paise**, including prices, offers, shipping, and order totals. Currency defaults to `INR`. Product and category slugs are unique; UUID primary keys are generated by PostgreSQL. Inventory starts at zero. Media files live in object storage; `product_images` stores only bucket/object keys and presentation metadata. No actual product photos or payment credentials belong in PostgreSQL.

The sample seed is optional and separate from migrations. Cart quotes use server-side prices. Real order creation and payment processing still require the payment integration and fulfilment rules.
